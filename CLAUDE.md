# CLAUDE.md — Eddie

_Создан из sdlc-starter-kit: 2026-08-13_

## О проекте

Eddie — локальный браузерный канвас ревью для AI-агентов Claude Code. Вход: путь к `.md`/`.html`-файлу (`eddie open <file>`). Агент блокируется на `eddie await <file>`, пока человек не оставит фидбек/правки/вердикт в браузере — выход: JSON с items+tasks+verdict. Публичный репо (MIT), ноль npm-зависимостей.

## Среда

Основная связка — **Claude Code, запущенный внутри Antigravity IDE**. Здесь идёт вся разработка. `AGENTS.md` рядом — пассивная страховка для других агентов (Cursor/Codex/Antigravity-нативный), если репо откроют в них; активного пайплайна через них нет.

## Поток работы (SDLC)

Любая нетривиальная фича идёт по этой цепочке:

1. **Spec** — `docs/specs/YYYY-MM-DD-<slug>.md` (что/зачем/scope/acceptance/human-test). Без спеки в код не лезем.
2. **Plan** (для крупного) — `docs/superpowers/plans/YYYY-MM-DD-<slug>.md`. Разбивка на шаги, проверки.
3. **Code** — реализуй мелкими шагами, после каждого — проверка.
4. **Smoke** — добавь `@check` в `smoke.py`, прогони `python smoke.py` → `PASS` (см. `docs/playbooks/SMOKE_CHECK.md`). Регрессионная сетка, растёт с каждой фичей.
5. **Human test** — что машина не проверит (UX, как смотрится) прогони сам (см. `docs/playbooks/HUMAN_TEST_PROTOCOL.md`). Без этого задача **не закрыта**.
6. **HTML-превью** на каждый артефакт (если фича рождает данные/отчёт) — auto-open, плашка «что проверять».
7. **Ship** — коммит с понятным сообщением + **доказательство в отчёте** (вывод smoke / скрин, Golden Rule #8), обновить `docs/CHANGELOG.md` если значимо.

## Golden Rules (нарушать нельзя)

Полный список — в `docs/conventions/golden-rules.md`. Ключевые:

- Секреты — только через `.env` / OpenClaw vault. Никогда не просить токен в чате.
- Output генераторов — в `data/<feature>/output/`, **никогда** в корень проекта.
- HTML-превью на любую генерацию → авто-open (`open file://...`) + плашка «что проверять» с тегами 🆕 🔧 👀 ℹ︎.
- `<meta refresh>` — НЕ ставить нигде и никогда (глоб. решение 2026-07-07). Свежесть — по таймштампу; ручной апдейт — кнопка «↻ Обновить».
- Не плодить абстракции пока не появилось 3+ похожих кейса.
- Без спеки на фичу — не пишем код.
- Не писать «готово / проверил» без доказательства в отчёте: вывод `smoke.py` или скриншот (Golden Rule #8).
- Перед новым инструментом — инвентарь: что уже есть в репо и на рынке, вывод одной строкой в спеку (Golden Rule #9).
- Пустой/нулевой результат без причины — недосбор, не результат: `null` только с `na_reason`, в smoke — санити-проверки на смысл (Golden Rule #10).
- В любом сравнении бейзлайн/оригинал — первым в ряду, с легендой и методологией (Golden Rule #11).
- Статус-отчёты: сводные цифры сверху, блоки «локально / в гите / на проде» (см. `docs/dryhands/working-rules.md`).

## Не делать

- Не коммитить `data/`, `.env`, `from/`, любые входные бинарники.
- Не плодить абстракции до того, как появилось 3+ похожих кейса.
- Не ставить `<meta refresh>` ни на каком HTML (сбрасывает state, мешает читать) — только кнопка «↻ Обновить».
- Не закрывать задачу без smoke-прогона и human-test сценария.
- Не пушить в продакшн без явной команды.
- Не отдавать пустые/нулевые данные молча: либо докопался другим путём, либо `na_reason` + пометка needs_review.
- Не строить своё, пока не проверил готовое в репо и на рынке.

## Auto-обновление знаний

Если в проекте есть Obsidian-вольт (`~/Obsidian/Projects/eddie/`) — веди его автоматически по триггерам:

- **Принято тех-решение** → ADR в `02 — Решения (ADR).md`
- **Изменён ключевой параметр** (модель / промпт / retrieval) → `Эксперименты/EXP-NNN-<slug>.md`
- **Добавлен источник данных** → `Источники/<slug>.md`
- **Конец сессии** → дописать в `Дневник/YYYY-MM-DD.md`

Никаких «хочешь я обновлю?» — просто делай и в конце сообщи одной строкой.
