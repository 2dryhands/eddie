# Smoke Check — дешёвый прогон «фича работает целиком»

Smoke ≠ unit-тест. Не проверяем каждую функцию, не пишем тест ДО кода. Один интеграционный прогон на фичу: «запустилось и выдало ожидаемое». Это закрывает дыру human-test'а — регрессии (старая фича сломалась незаметно), но без TDD-фундаментализма.

Файл проекта — `smoke.py` в корне. Запуск: `python smoke.py`. Выход: `PASS: N/N` (код 0) или `FAIL` (код 1).

## Зачем именно так (для Гоши)

Ты не читаешь код. «Я проверил, всё ок» от AI — не доказательство, а обещание. `smoke.py` превращает обещание в факт: AI запускает, вставляет вывод `PASS: 4/4` в отчёт. Видишь цифру — веришь. См. Golden Rule #8 (evidence-before-done).

## Как пишется один прогон

В `smoke.py` каждый прогон — функция с декоратором `@check`. Падает (`assert` / `raise`) = FAIL. Дошла до конца = PASS.

```python
@check
def parser_returns_rows():
    """Парсер на фикстуре выдаёт >= ожидаемого числа строк."""
    rows = run_parser("tests/fixtures/sample.html")
    assert len(rows) >= 10, f"ждал >=10 строк, получил {len(rows)}"
```

## Что покрывать — по типу проекта

| Тип | Минимальный smoke |
|---|---|
| Парсер / скрипт | прогон на 1 фикстуре, сверка числа/формата строк |
| Telegram-бот | ключевая команда отвечает непустым текстом, не падает |
| HTML-дашборд | собирается на тестовых данных, есть ключевой маркер (`<table`, заголовок) |
| API / сервис | главный эндпоинт отдаёт 200 и валидный JSON |

Плюс всегда: **импорт проекта без ошибок** (фундамент) и, где дёшево, **идемпотентность** (запустил дважды — не дублирует).

## Главное правило — smoke накапливается

На каждую **новую фичу** → новый `@check`. На каждый **починенный баг** → `@check`, который этот баг ловит (чтобы не вернулся). Так из smoke вырастает регрессионная сетка под твой масштаб — пишет её AI, а ты понимаешь по названию что она проверяет.

## Масштаб — не золоти всё

- Одноразовый скрипт «на раз» → можно без `smoke.py`, достаточно показать вывод прогона руками.
- Бот/сервис в регулярном пользовании → `smoke.py` обязателен, растёт с фичами.
- Прод с деньгами/клиентами → smoke + потом, при росте, докинуть настоящие тесты поверх.
