# Human Test Protocol

Type-check и unit-тесты проверяют код, но не feature. Без human-test регрессии всплывают на проде. Это **обязательный** шаг закрытия задачи (Golden Rule #6).

## Два слоя проверки — не путать

1. **Smoke (машина)** — то, что можно прогнать кодом: парсер выдал строки, бот ответил, HTML собрался. Живёт в `smoke.py`, см. [SMOKE_CHECK.md](SMOKE_CHECK.md). Дёшево, накапливается, ловит регрессии.
2. **Human-test (глаза)** — то, что машина проверить НЕ может: как смотрится в Telegram на мобиле, красиво ли, верный ли тон. Этот документ — про него.

И поверх обоих — **Golden Rule #8**: любой результат подкреплён доказательством в отчёте (вывод `smoke.py` / скриншот / фрагмент output'а). «Проверил, ок» без пруфа не принимается.

## Кто прогоняет

**AI-агент сам**, не перекидывает на Гошу. «Реализовал, проверь сам» — не принимается.

Только если фича требует чего-то, что AI не может (например, проверить как смотрится в Telegram на мобиле) — AI пишет в финальном отчёте: «техническая часть прогнана, для UX-проверки в Telegram нужны твои глаза».

## Структура сценария в спеке

В каждой спеке (`docs/specs/<slug>.md` пункт 7) — конкретные шаги:

```
1. Открыть X
2. Сделать Y
3. Ожидаемо увидеть Z
4. Edge-case: что будет при пустом/огромном/спецсимвольном вводе
```

Шаги должны быть **воспроизводимы** — другой человек/агент пройдёт по ним и получит тот же результат.

## Что покрывать обязательно

1. **Happy path** — самый частый сценарий использования. Работает?
2. **Edge cases** — пустой ввод, огромный ввод, спецсимволы, отсутствие сети, отсутствие файла.
3. **Идемпотентность** — что будет, если запустить дважды? Не дублирует? Не падает?
4. **Чистый старт** — на свежей машине / после `rm -rf data/` — поднимается?

## Финальный отчёт

Когда AI закрывает задачу, в сообщении Гоше:

```
✅ Готово. Доказательства:
- smoke: `python smoke.py` → PASS: 4/4 (вывод приложен ниже)
- happy path: открыл [URL], нажал [X] → увидел [Y]. OK.
- edge case A: ввёл пустую строку → корректно вернул [Z]. OK.
- edge case B: <...>

Результат: data/<feature>/output/<run>/preview.html (открыл автоматически, скрин приложен).
Что проверить глазами: <1-2 пункта, если есть>.
```

Пруф — не для красоты: Golden Rule #8 запрещает «готово» без вставленного вывода smoke / скриншота.

## Когда отчёт короче

Если фича — однострочный рефактор или правка опечатки в README — можно одной строкой: «починил, обновил, проверил визуально». Полный протокол — для всего, что меняет поведение.
